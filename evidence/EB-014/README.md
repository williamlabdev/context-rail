## What the five PRs show

1. **PR #3 — `feat/receipt-conclusion-first` (`3ae8481`, merge `1b4d5c5`).** The release detail opens with one outcome sentence (`release-outcome`) built only from recorded fields: promoted / rejected / deployment-failed / gate-blocked / awaiting-build / awaiting-approval / awaiting-deployment. When an earlier deployment attempt failed, the sentence is followed by that attempt's first non-passing gate. The Release Receipt card moves directly under the outcome (previously it sat at the very bottom of the page). Gate tables now list only non-PASS rows; PASS rows fold into a `<details>` "N of M gates passed" disclosure that keeps its row testids in the DOM for audit. "發布 Receipt" becomes "發布收據". Also fixes card/badge overflow at ~1000px width (project map decision codes, change-card badges).
2. **PR #4 — `fix/workspace-readability-polish` (`667584f`, `7ad5413`, merge `b6e230c`).** The Project Context page's Decisions list now shows a human status label with the machine code kept small and secondary (reusing `StatusBadge`), instead of a raw `CODE -> STALE (topology vN)` string that broke mid-word in narrow columns. `ChangesPanel` defaults to the first Change in list order when nothing is selected yet, instead of an empty "Select a Change" placeholder (an explicit or in-progress selection is never overridden). The Changes section's flow line is now fully localised in zh-TW ("Brief" translated; "Agent Context Pack" / "Work Order" stay English per the dictionary's documented convention for machine artifact names).
3. **PR #5 — `feat/release-technical-report` (`c96ad95`, `dde6953`, merge `f58a350`).** `ReleaseDetail` splits into a **Summary** view (default: outcome sentence, a human-readable receipt summary with no full sha256, a plain "Changes in this release" list naming each Change by id + title, only the gates still blocking, and every action form) and a **Technical report** view (full heading with all hashes, the full receipt card, the promotion delta card, the MANIFEST table, the full gate table including PASS rows, and every deployment attempt including already-promoted ones). The toggle (`release-view-summary` / `release-view-technical`) is pure display state; the renderer adds no facts, only selects/orders/relabels recorded fields. Implements readability review item 5.
4. **PR #6 — `fix/brief-reader-preview` (`cf9de5c`, merge `a505762`).** Three fixes to `ChangeBrief.tsx` surfaced by an AI-preview of Brief v2 (two independent sonnet-subagent readers, screenshot-only, one per locale — see [reader-test doc](../../docs/validation/CONTEXT_RAIL_BRIEF_READER_TEST_2026-09-25.zh-TW.md) §9): (a) when both `in_scope` and `out_of_scope` are empty, one merged "Scope" line replaces two boxes that each said "no explicit list" (read as circular); (b) required-evidence codes show only the human label, with the raw code moved to a title tooltip instead of sitting in the reader's text (an unlabeled code still shows as-is); (c) "Considered, not chosen" gets a top divider and a per-alternative "Not chosen:" label, so it can no longer be misread as continuing the decided-by rationale directly above it. New Brief screenshots were captured for the human reader test; the AI-preview's own scores (5/6 each) and verbatim answers are recorded in the doc but **explicitly excluded from G5**.
5. **PR #7 — `docs/reader-test-zh-material` (`115eb13`, `e7de1c5`, merge `753900c`).** The prior zh-TW reader-test screenshot showed zh-TW UI chrome with **English free text** in every data field (owner_summary, scope, rationale), because both screenshots had been captured from the same English-authored request — the renderer never translates data, so this would have tested a non-engineer zh-TW reader on English vocabulary, not on Brief structure. Replaced with `tests/browser/reader-test-material.capture.ts` (+ its own Playwright config), a committed, repeatable script that drives the real Change→decision UI flow twice — once with an English-authored request, once with the same meaning written natively in Traditional Chinese by the requester — producing fresh `brief-en.png` / `brief-zh-TW.png`. The script is excluded from `npm run test:e2e` by filename, not by a config exclusion list.
