1. **Title** — ContextRail: environment-aware AI Change Assurance. One line: *prove the change still matches the accepted intent before each governed environment — with evidence read back from where the change actually lives.* Team, deployed URL `<DEPLOYED_URL — fill after 2026-10-06>`, both public repos (`williamlabdev/context-rail`, `williamlabdev/order-operations-portal`).
2. **The problem** — AI coding agents accelerate change; startup/SMB teams (5–30 engineers, Git + CI + an AI assistant, ≥2 environments, no platform team) lose the answers to *what was accepted, did the agent stay in scope, is the deployed image the reviewed change*. Cost of a wrong promotion. One-line contrast: the agent's report says "done and tested" — who checked?
3. **The hero path** — the diagram from `README.md`: contract → topology → decision pack → work order → candidate gate → release → receipt → prod-demo. Three separate human decisions; deterministic gates block but never approve. Footer: *slide 6 shows this running once, for real, on a live GitHub repository.*
4. **Contract before execution** — Project Context Contract (`internal/projectregistry`, `demo/order-operations-portal/project.yaml`), versioned topology (`internal/topology`, production read-only), document baseline with missing → readiness mapping (`internal/document`), Context Pack that says `PARTIAL` instead of inventing. Screenshots: `evidence/EB-010/documents-partial-pack.png`, `evidence/EB-011/topology-en.png` + `topology-zh-TW.png`.
5. **Decision Pack, honestly** — `NEEDS_INPUT` names the missing input's owner; an advisor proposes (rule-based `internal/change/advisor.go: RuleAdvisor`, or Gemini via `GeminiAdvisor` when `GEMINI_API_KEY` is set — **no run with a real key has been observed yet; today's evidence is the rule advisor**); a human decides; one DecisionRecord renders a Brief for people and an Agent Context Pack for the agent from the same lineage; a hashed Work Order follows. Real example: `CHG-001 Order exception evidence links` → `DEC-001 founder-001 minimal_reversible_slice` → `AWO-001 sha256:952c8da4…`. The Brief itself went through two readability passes this week (`docs/reviews/CONTEXT_RAIL_BRIEF_READABILITY_REVIEW_2026-09-25.zh-TW.md`): plain-language summary first, hashes collapsed into "trace info," and a fix for a reader-confusion bug (`fix/brief-reader-preview`, `frontend/src/components/ChangeBrief.tsx`) caught by an AI preview reader. **The human reader test itself (2–3 people, "what was approved / not approved / biggest risk") is prepared but not yet run** — the readability claim is "an AI reader stopped getting confused," not "a person proved it's readable." Screenshots: `evidence/EB-012/dec-001-decision.png`, `evidence/EB-012/awo-001-work-order.png`, `docs/validation/reader-test-materials/brief-zh-TW.png`.
6. **Provenance over assertion — proven on a real pull request** — the candidate gate evaluates what GitHub returns (compare, pull request, reviews, check runs), not what the agent declared (`internal/change/candidate.go`). Screenshots: `evidence/EB-012/cand-001-needs-review.png`, `evidence/EB-012/cand-002-gates-accepted.png`; small inset of the PR. Second bullet: out-of-scope path → `BLOCKED` with the path named (`evidence/EB-007/candidate-review.png`).
7. **Same digest is necessary, not sufficient** — release bundle gate (one blocked change blocks the bundle), build must include the accepted commit, third approval bound to the manifest hash, deployment verification against the live Cloud Run revision (digest / target / config drift, smoke, idempotency), Release Receipt (`internal/release`). This week's readability pass (`feat/receipt-conclusion-first`, `feat/release-technical-report`, `frontend/src/components/ReleasesPanel.tsx`): the release opens with **one outcome sentence** built only from recorded fields, non-passing gates only (passing gates fold into "N of M gates passed"), and a **Summary / Technical report toggle** — the decision-maker sees the outcome and the receipt, the auditor's Technical report has the full hash chain, manifest table and every deployment attempt. Prod-demo promotion carries an environment delta and a chained receipt. 10. **Built on Google Cloud** — Cloud Run hosts the workspace and is the promotion target for staging and prod-demo `[VERIFY AFTER DEPLOY]`; Cloud Build + Artifact Registry build the image, `scripts/deploy-cloud-run.sh` and `cloudbuild.yaml` promote by digest only `[VERIFY AFTER DEPLOY]`; Gemini is available as the decision advisor (`internal/change/advisor.go: GeminiAdvisor`) and is designed to propose, never decide, with output marked UNVERIFIED — **no live-key run exists yet, so this slide states the design, not an observed result** `[VERIFY AFTER DEPLOY]`; `scripts/record-promotion.sh` reads the live Cloud Run revision and digest with `gcloud` and records the observation with an idempotency key `[VERIFY AFTER DEPLOY]`.
11. **Evidence, boundaries, and what's next** — ContextRail is built the way it asks its users to build: every slice has a `DR-nnn` decision record and an `EB-nnn` evidence bundle (Go + HTTP tests, Playwright journeys, consumer-fixture hash before/after, screenshots) under `decisions/` and `evidence/`; `evidence/EB-012` closes the loop on a real repository. Boundaries (P0, see `README.md`): no production execution; governance state is JSON on disk, Firestore is a later step — **no Firestore, Cloud Storage or embedding is implemented today**; the `X-ContextRail-Actor` header is recorded, not authenticated; ledger ids are not yet reconciled with the consumer's own ids (found while verifying EB-012). Roadmap: Firestore-backed state, in-service Cloud Run read-back, id-namespace reconciliation, rollback, human reader test for the Brief (G5). **Direction, not a feature:** `docs/decisions/ADR-002-a2a-extension.zh-TW.md` (Status: Proposed) explores a possible Agent-to-Agent protocol adapter for cross-provider independent review and out-of-scope escalation; it amends ADR-001's reconsideration gate, is explicitly **not implemented**, and its own text states its Stage B will not ship before this Cup's submission deadline — shown here only as a next-step direction under review, never as a shipped capability.
