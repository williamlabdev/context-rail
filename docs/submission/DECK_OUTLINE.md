# ContextRail — submission deck outline (10 slides)

Every screenshot referenced below exists today under `evidence/`; slides 7–8 get their live shots on 10/8 (Cloud Run) and fall back to the EB-008/EB-009 fixture screenshots until then.

1. **Title** — ContextRail: environment-aware AI Change Assurance. One line: *prove the change still matches the accepted intent before each governed environment — with evidence read back from where the change actually lives.* Team, Cloud Run URL, both public repos (`williamlabdev/context-rail`, `williamlabdev/order-operations-portal`).
2. **The problem** — AI coding agents accelerate change; startup/SMB teams (5–30 engineers, Git + CI + AI assistant, ≥2 environments, no platform team) lose the answers to *what was accepted, did the agent stay in scope, is the deployed image the reviewed change*. Cost of a wrong promotion. One-line contrast: the agent's report says "done and tested" — who checked?
3. **The hero path** — the diagram from the README: contract → topology → decision pack → work order → candidate gate → release → receipt → prod-demo. Three separate human decisions; deterministic gates block but never approve. Footer: *all of it ran once, for real — slide 6.*
4. **Contract before execution** — Project Context Contract (`project.yaml`), versioned topology (production read-only), document baseline with missing → readiness mapping, Context Pack that says `PARTIAL` instead of inventing. Screenshots: `evidence/EB-010/documents-partial-pack.png`, topology (`evidence/EB-011/topology-en.png`).
5. **Decision Pack** — `NEEDS_INPUT` with owners; advisor (rule-based, Gemini with a key) proposes, a human decides; one DecisionRecord → Brief + Agent Context Pack with the same lineage; hashed Work Order. Real example: `CHG-001 Order exception evidence links` → `DEC-001 founder-001 minimal_reversible_slice` → `AWO-001 sha256:952c8da4…`. Screenshots: `evidence/EB-012/dec-001-decision.png`, `evidence/EB-012/awo-001-work-order.png`.
6. **Provenance over assertion — proven on a real pull request** — the candidate gate evaluates what GitHub returns (compare, pull request, reviews, check runs), not what the agent declared. Real run (EB-012): agent `claude-cowork` implemented REQ-002 on `williamlabdev/order-operations-portal`, PR #1, CI `test`/`build` green. **CAND-001: every technical gate PASS, still refused — `independent_review NEEDS_REVIEW`.** CAND-002 after a separate AI review + documented single-operator controls: `WAIVED`, `CANDIDATE_ACCEPTABLE`, accepted by `founder-001` (staging only, never production). Screenshots: `evidence/EB-012/cand-001-needs-review.png`, `evidence/EB-012/cand-002-gates-accepted.png`; small inset of the PR. Second bullet: out-of-scope path → `BLOCKED` with the path named (`evidence/EB-007/`).
7. **Same digest is necessary, not sufficient** — release bundle gate (one blocked change blocks the bundle), build must include the accepted commit, approval bound to the manifest hash, deployment verification against the live Cloud Run revision (digest / target / config drift, smoke, idempotency), Release Receipt; prod-demo promotion with environment delta and chained receipts. Screenshots: receipt chain (`evidence/EB-009/prod-demo-receipt.png` → replaced by the 10/8 real receipt).
8. **Everything that moves goes STALE** — topology edit after approval (`UI-14`), lineage change after a receipt, document declared after a decision: dependent decisions are marked `STALE`, never silently reused. Screenshots: `evidence/EB-008` / `EB-009` STALE shots, `evidence/EB-010/documents-partial-pack.png`.
9. **Built on Google Cloud** — Cloud Run (workspace + staging + prod-demo services), Cloud Build + Artifact Registry (digest-only promotion, `cloudbuild.yaml`, `scripts/deploy-cloud-run.sh`), Gemini as decision advisor (proposes, never decides; output marked UNVERIFIED), `scripts/record-promotion.sh` reading live revisions with `gcloud`; Firestore as the next persistence step.
10. **Evidence and next steps** — ContextRail is built the way it asks its users to build: every slice has `DR-nnn` + `EB-nnn` (Go + HTTP tests, 13 Playwright journeys, consumer-fixture hash before/after, screenshots); 20/20 UI cases executable; CI green on the public repo (`go` · `frontend` · `browser` jobs, fixture hash asserted in CI); **EB-012 closes the loop on a real repository**. Boundaries (P0): no production execution, JSON state, actor recorded not authenticated, ledger ids not yet reconciled with the consumer's own. Roadmap: Firestore, Cloud Run read-back inside the service, id namespaces, rollback stretch.
