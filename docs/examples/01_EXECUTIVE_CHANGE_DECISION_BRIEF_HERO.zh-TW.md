# Executive Change Decision Brief

> **示例資料／非真實部署證據**

## 這份報告給誰

給 Business Owner、主管與 PM。這份報告只保留「是否值得做、風險是否可接受、現在需要誰決定」；不要求讀者理解 Cloud Run、Cloud Storage 或 signed URL 的技術細節。

## Project 環境與目前位置

這個 Project 的團隊自行定義了 `Development → Testing → Staging → Production`。這次變更目前停在 **Staging gate**：可以準備受控驗證，但不能直接進入正式環境；每往下一個環境，都要有該環境要求的證據與負責人批准。

## 一句話結論

**建議進行，但先在受控的測試環境驗證。檔案只允許經授權的使用者存取，系統會提供短時間有效的臨時連結。正式上線前，還需要確認實際成本、資安審查、備份與復原能力，以及完整的上線驗證結果。**

## 為什麼值得做

目前申請資料與附件分散在不同地方，審核者可能找不到檔案，或看到不該看的檔案。把附件放回申請流程，可以減少審核遺漏、權限錯誤與人工追檔成本。

## 對業務的影響

| 現在的問題 | 預期改善 | 需要接受的代價 |
|---|---|---|
| 審核者找不到附件 | 在申請單內直接查看 | 需要定義檔案格式與保留期限 |
| 附件權限不一致 | 沿用申請單的角色權限 | 需要驗證申請人、審核者與無關人員 |
| AI 直接修改系統風險高 | 先確認決策與限制，再讓 AI 協助開發 | 多一個審查步驟，但降低錯誤變更風險 |

## 本次批准與不批准的事

| 項目 | 決定 |
|---|---|
| 先做測試環境驗證 | 可以 |
| 只讓授權使用者存取附件 | 必須 |
| 直接影響正式環境使用者 | 不批准 |
| 建立通用檔案管理平台 | 不在本次範圍 |
| 自動批准或自動上正式環境 | 不批准 |

## 正式上線前的必要條件

1. 以真實測試流量確認儲存與下載成本。
2. 完成資安與資料分類審查。
3. 證明檔案備份、保存與復原方式可行。
4. 完成測試環境上線驗證，並確認實際部署內容與審查版本一致。

## 需要誰做下一個決定

| 角色 | 要確認的事 |
|---|---|
| Product Owner | 使用者、檔案格式、流量與保留期限 |
| Security Owner | 資料分類、存取規則與資安政策 |
| Solution Architect | 技術方案與服務影響 |
| Release Owner | 測試環境驗證與正式上線 gate |
